# ハンズオン 8-A: エージェントのツール化を動かす

研修コース「LangChain による Agentic AI 開発実践」/ 第8章「マルチエージェント開発」

Subagents 型マルチエージェントの**コアメカニズム**——「エージェントをツールとして
ラップする」——を、最小構成で動かして体験するハンズオンです。

> **この章のキーメッセージ**: マルチエージェントに新しい API はほとんど登場しません。
> `@tool` (第3章)・`create_agent` (第3章)・`invoke` (第3章) の**組み合わせ**で、
> エージェント自身を「ツール」に変えるだけです。

---

## このハンズオンで動かすもの

```
hands-on/
├── README.md                  # この手順書
├── requirements.txt           # 依存パッケージ (ピン留め済み)
└── handson_8A_subagents.py    # research サブエージェント 1 体を @tool でラップ → supervisor が呼ぶ
```

構成は「PM (supervisor) と専門チーム (research サブ)」のアナロジーです。

```
ユーザー → supervisor → research ツール → research_agent → 調査結果を supervisor に返す → 応答
```

- `research_agent` … `create_agent(..., name="research_agent")` で作った調査専門のサブエージェント
- `call_research_agent` … それを `@tool("research", ...)` でラップした関数。
  サブを `invoke` し、`result["messages"][-1].content` (最終メッセージだけ) を返す
- `supervisor` … `create_agent(MODEL, tools=[call_research_agent])`。サブを「ただのツール」として呼ぶ

## セットアップ (第5章ハンズオン 5-A の続き)

実行環境は **Google Cloud Shell** (Linux) です。**第5章ハンズオン (5-A) で、リポジトリの
clone・仮想環境 (venv) の作成・`.env` の設定 (OpenAI + LangSmith) は完了している前提**です
(本章はそこに新しい clone や `.env` 作成を足しません)。

1. (新しいタブの場合は) リポジトリ直下の venv を有効化:
   ```bash
   source <リポジトリ>/.venv/bin/activate
   ```
2. このディレクトリへ移動:
   ```bash
   cd <リポジトリ>/chap08/hands-on
   ```
3. このディレクトリの依存をインストール:
   ```bash
   pip install -r requirements.txt
   ```

> **API キー / LangSmith について:** API キーはリポジトリのルートの共通 `.env` に記入済みです
> (5-A で設定)。スクリプトは先頭で `load_dotenv()` を呼び、ルートの `.env` を読み込みます。
> `LANGSMITH_TRACING=true` により、このハンズオンの実行は自動的に LangSmith に記録されます。

## 実行する

```bash
python handson_8A_subagents.py
```

同じ依頼を **2 回**実行します。どちらの回も、supervisor が `research` ツール (= サブエージェント)
に調査を委譲し、その結果を踏まえて回答する様子が出力されます。

### 期待される出力 (例)

```

1 回目: subagents というマルチエージェントの方式について教えて
======================================================================
[supervisor の最終回答]
Subagents は、メインエージェント (supervisor) がサブエージェントをツールとして呼び出す方式です。
ルーティングはすべて supervisor を経由します。...

======================================================================
2 回目 (同じ依頼): subagents というマルチエージェントの方式について教えて
```

## LangSmith トレースで確認すること (このハンズオンの主目的)

LangSmith は**コース全体で有効化済み**です。実行後に [smith.langchain.com](https://smith.langchain.com)
でプロジェクト (既定 `langchain-training-day2`) を開き、次の 3 点を確認してください。

### 1. 入れ子構造 (supervisor の内側にサブエージェントがいる)

トレースを開くと、supervisor の 1 ターンの中に `research` ツールの呼び出しがあり、
**その内側に** `research_agent` の ReAct ループ (モデル呼び出しと `search_docs` の実行) が
入れ子で表示されます。`name="research_agent"` を付けたおかげで、入れ子のどれがサブエージェントか
ひと目で分かります。

```text
supervisor (1ターン)
├── モデル呼び出し ①: research ツールの使用を決定
├── Tool: research
│   └── research_agent          ← name 引数で識別できる
│       ├── モデル呼び出し ②: search_docs の使用を決定
│       ├── Tool: search_docs
│       └── モデル呼び出し ③: 結果を最終メッセージにまとめる
└── モデル呼び出し ④: ユーザーへの応答を作成
```

### 2. モデル呼び出しは 4 回

数えてみてください——1 回の依頼でモデル呼び出しは **4 回**です。これは 8-2 節の One-shot
シナリオ「Subagents は 4 回」の理論値が、**自分のトレースで実測できる数字**であることの確認です。
サブの結果が必ず supervisor を 1 回経由する分だけ、単一エージェントより 1 手多くなります
(集中制御の対価)。

### 3. 1 回目と 2 回目で呼び出し回数は変わらない (stateless の裏取り)

2 回目のトレースも、1 回目と同じ 4 回です。**Subagents のサブエージェントは stateless** で、
呼ばれるたびにまっさらなコンテキストで起動するため、繰り返しの依頼でもコストは減りません。
これは「強いコンテキスト分離の裏返し」であって欠陥ではない——8-2 節で学んだトレードオフを、
ここで実測として裏取りします。

## コードリーディングのポイント

実行できたら、ソースを開いて次の 3 点を確認してください。

1. **新しい API はない** — `create_agent` も `@tool` も `invoke` も、すべて第3章で学んだもの。
   変わったのは「ツールの中身がサブエージェントの呼び出しになった」ことだけ。
2. **`name="research_agent"`** — トレースでサブを識別するための表示名。
3. **`result["messages"][-1].content`** — サブに返ってくる中から「最終メッセージだけ」を取り出して
   supervisor に渡している。だからサブの system_prompt で「結果は必ず最終メッセージに含める」と
   念押ししている (これを怠ると「調査しました」だけが返り、肝心の中身が消える)。

## うまくいかないときは

| 症状 | 確認すること |
|---|---|
| `OPENAI_API_KEY` 関連のエラー | リポジトリのルートに `.env` を作成し、キーを記入したか (5-A の手順) |
| トレースが記録されない | ルートの `.env` に `LANGSMITH_TRACING=true` と `LANGSMITH_API_KEY` があるか |
| 呼び出し回数が 4 でない | モデルが research を呼ばず直接答えた可能性。質問を変えず再実行し、トレースで確認 |
